- Aplicar `@override` para indicar intención de sobrescritura
- Conocer las mejoras de Python 3.13 relevantes para código de producción

## 1. keyword `type` (Python 3.12)

Antes de 3.12, los alias de tipo eran simples asignaciones que mypy interpretaba:

```python
# Python 3.10/3.11 — TypeAlias
from typing import TypeAlias

ProjectId: TypeAlias = int
AssetFilter: TypeAlias = dict[str, list[str]]
```

Python 3.12 introduce el keyword `type`, que crea un alias real con semántica propia:

```python
# Python 3.12+ — keyword type
type ProjectId = int
type ClientId = int
type AssetFilter = dict[str, list[str]]
type AssetRecord = dict[str, str | int | float]

# También admite genéricos
type Matrix[T] = list[list[T]]
type Callback[**P, R] = Callable[P, R]
```

### Diferencias con `TypeAlias`

| | `TypeAlias` (3.10+) | `type` keyword (3.12+) |
|---|---------------------|----------------------|
| Sintaxis | `Name: TypeAlias = ...` | `type Name = ...` |
| Lazy evaluation | No | Sí (el tipo no se evalúa hasta que se usa) |
| Introspección | Limitada | `__value__` accesible |
| Genéricos | Con `TypeVar` explícito | Sintaxis inline `[T]` |
| Preferido en | 3.10/3.11 | 3.12+ |

```python
# Lazy evaluation — útil para tipos recursivos
type JSON = str | int | float | bool | None | list["JSON"] | dict[str, "JSON"]
# Con TypeAlias esto era complicado, con type funciona directo
```

## 2. F-strings mejoradas (Python 3.12)

Python 3.12 elimina varias restricciones de las f-strings:

### Comillas anidadas — ya no hay restricción

```python
# Python 3.11 y anteriores — debías alternar comillas
name = "Studio BC"
msg = f"Project: {name!r}"                  # OK
msg = f"Length: {len('hello')}"             # OK
# msg = f"{'inner string'}"                 # ❌ en 3.11

# Python 3.12+ — cualquier combinación de comillas
msg = f"{'inner string'}"                    # ✅
msg = f"Name: {'Studio BC'.upper()}"         # ✅
msg = f"Tags: {', '.join(['video', 'raw'])}" # ✅
```

### Expresiones multi-línea

```python
# Python 3.12+ — f-strings multi-línea completas
report = f"""
Project: {project.name}
Client: {
    client.name.upper()
    if client.active
    else 'INACTIVE'
}
Budget: ${project.budget:,.2f}
Assets: {len([
    a for a in project.assets
    if a.status == 'uploaded'
])} uploaded
"""
```

### Backslashes dentro de f-strings

```python
# Python 3.12+ — backslashes permitidos dentro de {}
files = ["video.mp4", "thumb.png", "script.pdf"]
listing = f"Files:\n{'\n'.join(f'  - {f}' for f in files)}"
```

## 3. `@override` (Python 3.12)

`@override` documenta la intención de sobrescribir un método y permite que mypy detecte errores:

```python
from typing import override

class BaseProcessor:
    def process(self, asset_path: str) -> bool:
        return True

    def validate(self, asset_path: str) -> list[str]:
        return []

class VideoProcessor(BaseProcessor):
    @override
    def process(self, asset_path: str) -> bool:    # ✅ sobrescribe correctamente
        return self._transcode(asset_path)

    @override
    def validte(self, asset_path: str) -> list[str]:   # ❌ mypy error: typo, método no existe en base
        return []

    def _transcode(self, path: str) -> bool:
        return True
```

Sin `@override`, el typo `validte` crearía un método nuevo silenciosamente en lugar de sobrescribir. Con `@override`, mypy lanza un error.

## 4. Mejoras en mensajes de error (Python 3.12/3.13)

Python 3.12 y 3.13 mejoran significativamente los mensajes de error para facilitar el debugging:

```python
# Python 3.11 — mensaje genérico
# TypeError: 'NoneType' object is not subscriptable

# Python 3.12+ — mensaje con contexto
data = None
data["key"]
# TypeError: 'NoneType' object is not subscriptable
# Hint: 'data' is None — did you forget to initialize it?
```

### NameError mejorado

```python
import math

result = match.sqrt(16)   # typo
# Python 3.11: NameError: name 'match' is not defined
# Python 3.12: NameError: name 'match' is not defined. Did you mean: 'math'?
```

## 5. Python 3.13 — principales novedades

### `TypeIs` — narrowing bidiferencial

Ya visto en el archivo de type system. Recapitulando:

```python
from typing import TypeIs   # Python 3.13

def is_str(val: str | int) -> TypeIs[str]:
    return isinstance(val, str)

x: str | int = get_value()
if is_str(x):
    x.upper()    # x es str ✅
else:
    x + 1        # x es int ✅ (TypeIs hace narrowing en else también)
```

### `warnings.deprecated` y `@deprecated`

```python
from warnings import deprecated

@deprecated("Use process_asset_v2() instead")
def process_asset(path: str) -> bool:
    ...

# Mypy y editores muestran el mensaje de deprecación
process_asset("/media/video.mp4")   # DeprecationWarning en runtime + warning en IDE
```

### Intérprete interactivo mejorado (REPL)

Python 3.13 incluye un REPL completamente rediseñado con:
- Multi-línea con historial
- Coloreado de sintaxis
- Autocompletado mejorado

```
$ python3.13
>>> def greet(
...     name: str,
...     title: str = "Sr/Sra",
... ) -> str:
...     return f"Hola, {title} {name}"
...
>>> greet("García")
'Hola, Sr/Sra García'
```

### No-GIL experimental (Python 3.13t)

Python 3.13 incluye una build experimental sin GIL (`python3.13t`), habilitando verdadero paralelismo en threads para código CPU-bound. Aún experimental — no usar en producción.
